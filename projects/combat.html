Advanced Combat System

Server-authoritative hits, combo system, prediction for visuals, and AI reaction states.

Overview

This combat system balances responsiveness with security. Clients predict animations and sound immediately for player feel; the server validates hits and resolves damage to prevent cheating. The example code demonstrates a clear separation between client-only visual prediction and server-side authoritative logic.

Architecture

  1. Client Input Layer — records inputs and plays local animation (non-authoritative).
  2. Prediction Layer — client-side animation/visual prediction to hide latency.
  3. Server Validation Layer — receives attack events, runs raycasts and timestamp checks, applies damage.
  4. State Manager — manages stagger, block, invulnerability windows, and animation tags.
  5. AI Integration — enemies respond to events (damage, player proximity) through a simple state machine.

Security & Networking Notes

  • Always validate hits on the server: use authoritative raycasts and check reported timestamps against server time (with tolerance).
  • Use short input buffers on client for combos, but send explicit inputs to server for validation before permanently applying effects.
  • Prevent teleport/exploit by checking distances and ensuring hit positions are near the target's current server position.

API Surface (recommended)

-- Server API
Combat:RegisterAttack(player, attackData) -- attackData includes timestamp, animationTag, hitTrace
Combat:ValidateHit(attacker, targetId, hitPos, timestamp) -> boolean
Combat:ApplyDamage(target, amount, hitType)

-- Client API
Combat:PlayLocalAnimation(player, animationTag)
Combat:QueueComboInput(player, inputName)

Testing & Performance

  • Unit test server validation logic with mocked positions and timestamps.
  • Stress test with multiple concurrent attacks and high player counts to ensure server raycasts scale (consider spatial partitioning).
  • Profile the server for raycast-heavy bursts; use simplified area checks where precise raycasts aren't necessary.

Example snippet (server-side hit validation)

-- server: validate hit from client
local function validateHit(attacker, targetId, reportedPosition, timestamp)
  -- Accept small clock skew (e.g., 2s) but reject stale/teleport attempts
  if math.abs(os.time() - timestamp) > 2 then return false end
  local target = workspace:FindFirstChild(targetId)
  if not target then return false end

  -- server-side trace to validate reachability
  local origin = attacker.Character.Head.Position
  local direction = (reportedPosition - origin)
  if direction.Magnitude > 12 then return false end -- max reach
  local ray = Ray.new(origin, direction.Unit * direction.Magnitude)
  local hitPart, hitPos = workspace:FindPartOnRay(ray, attacker.Character)
  if hitPart and hitPart:IsDescendantOf(target) then
    return true
  end
  return false
end

Flight System

Client prediction, input smoothing, lift/drag approximations, and camera follow behavior for a smooth flying experience.

Overview

The flight system focuses on player feel: low input latency, smooth transitions, and believable arcade-like aerodynamics. Networking uses prediction on the client and reconciliation from the server to correct drift.

Architecture

  1. Input smoothing & deadzone handling to reduce jitter
  2. Client-side physics simulation for immediate response
  3. Server-side authoritative simulation at lower frequency for final position/state
  4. Reconciliation logic to apply authoritative corrections smoothly

Networking Patterns

  • Send compact state snapshots (position, velocity, angularVelocity) at a steady rate.
  • On client: predict movement locally using inputs; buffer recent inputs for re-simulation when server snapshot arrives.
  • When reconciling, smoothly blend the visual position to the server-corrected position to avoid teleportation.

API Surface

-- Client
Flight:SendInput(player, rawInput) -- rawInput: Vector3 throttle/strafe
Flight:Predict(dt)

-- Server
Flight:ReceiveInput(playerId, inputSnapshot)
Flight:SimulateServer(dt) -- lower-frequency authoritative sim

Performance & Tuning

  • Keep client simulation stable at variable dt — use semi-implicit integration.
  • Limit physics substeps on server to a reasonable rate (e.g., 30 Hz) and interpolate between snapshots.
  • Use deadzones and exponential smoothing for stick inputs to improve feel.

Example snippet (input smoothing)

-- exponential smoothing
local alpha = 0.12 -- smoothing factor (smaller = smoother)
local smoothed = Vector3.new(0,0,0)
function smoothInput(raw)
  smoothed = smoothed:Lerp(raw, alpha)
  return smoothed
end
